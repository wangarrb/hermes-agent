# Codex Kanban Root Session Resume Design

## Problem

The Codex kanban launcher resolves the most recently updated thread for a
profile workspace and passes it to `codex resume`. Codex persists both the
interactive root thread and its multi-agent v2 sub-agent threads in the same
`threads` table. A sub-agent can therefore sort ahead of its parent.

Codex cannot cold-resume such a sub-agent through the TUI. It requires the
parent thread to be loaded first, so selecting a sub-agent causes the reviewer
pane to fail during bootstrap.

## Root cause

`plugins/kanban/session_scope.py::latest_codex_thread` filters by archive state
and canonical workspace only. It does not distinguish resumable root threads
from `thread_source = 'subagent'` rows. On 2026-09-09 it selected
`01a084ee-dcf0-7140-9c71-7dba149e6138` instead of its existing parent
`01a08481-82dd-7b00-8798-2fc8ac752592`.

## Design

Keep session selection in `latest_codex_thread`, but restrict candidates to
root threads when the installed Codex state schema exposes source metadata.
Classify each returned row in Python so mixed plain-text and JSON `source`
values cannot make a whole SQLite query fail.

- Exclude an explicit `thread_source = 'subagent'`.
- Also inspect `source` when `thread_source` is absent, `NULL`, or empty.
  Exclude either the plain value `subagent` or a valid JSON object with a
  top-level `subagent` member.
- Treat plain root values such as `cli`, `exec`, and `unknown`, malformed JSON,
  and rows with no source metadata as legacy root candidates. JSON parsing is
  best-effort per row and never rejects the entire database.
- Preserve compatibility with older schemas that expose neither column by
  retaining the existing workspace-and-recency selection.
- Do not mutate, archive, rename, or delete session rows or rollout files.
- Keep the listener API and launch command unchanged; it will receive the
  selected root thread ID as before.

The source filtering belongs in the selector rather than the launcher because
the selector owns the resumability decision and can be tested independently.

## Tests

Add a regression case using a temporary Codex state database containing:

1. An older root thread for the requested workspace.
2. A newer sub-agent thread for the same workspace.
3. An unrelated newer root thread for another workspace.

The selector must return the requested workspace's root thread. Cover these
storage variants separately:

1. Current schema with an explicit `thread_source = 'subagent'`.
2. A `source`-only schema with a JSON sub-agent object.
3. A transitional row with empty/`NULL` `thread_source` and JSON sub-agent
   metadata in `source`.
4. Plain or malformed `source` values, which must not abort selection.
5. A legacy schema with neither source column, which keeps current behavior.

Existing tests must continue to cover exact canonical-workspace matching.

Run the focused selector/listener tests, then the surrounding kanban listener
test group.

## Operational recovery

After tests pass, confirm that no failed reviewer watcher or Codex process is
still live for `kanban-seqscale:2`. The normal safe-boundary command is:

```bash
local/bin/hermes-kanban-switch-reviewer-mode \
  --board seqscale --mode balanced --session kanban-seqscale \
  --workspace /home/wyr/code/SeqScale
```

It is valid only when the pane has a live, empty Codex composer. The current
bootstrap-error screen does not meet that precondition, so recovery must use
the same command generated by the script's `--dry-run` output to replace only
pane 2: save the currently focused pane, focus pane 2, call `zellij new-pane
--in-place --close-replaced-pane`, then restore the previous focus. This is the
same replacement sequence used by the switch script after its safety check;
the explicit process check makes it safe for the already-dead bootstrap case.

Confirm afterward that exactly one reviewer watcher is live, its Codex command
resumes parent thread `01a08481-82dd-7b00-8798-2fc8ac752592`, and the pane
